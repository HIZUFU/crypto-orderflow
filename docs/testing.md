# Testing guide

Полное тестирование приложения на локальном ПК с диска `D:`.

## Этап 1: Установка и базовая проверка (10 минут)

### 1.1 Клонирование репозитория

Открой PowerShell и выполни:

```powershell
New-Item -ItemType Directory -Force D:\Projects
Set-Location D:\Projects
git clone https://github.com/HIZUFU/crypto-orderflow.git
Set-Location crypto-orderflow
```

### 1.2 Создание виртуального окружения

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell блокирует активацию, используй:

```powershell
D:\Projects\crypto-orderflow\.venv\Scripts\python.exe -m pip install --upgrade pip
```

### 1.3 Установка зависимостей

```powershell
pip install -e ".[dev]"
```

Это установит FastAPI, SQLite, NumPy, pytest, ruff и все базовые библиотеки.

### 1.4 Настройка конфигурации

```powershell
Copy-Item .env.example .env
```

Проверь файл `.env`: там должно быть `TRADING_MODE=paper` и `LIVE_TRADING_ENABLED=false`.

### 1.5 Запуск тестов

```powershell
pytest
ruff check .
```

Все тесты должны пройти успешно. Если pytest выдаёт ошибки импорта, переустанови зависимости.

## Этап 2: Запуск paper-режима (30 минут–несколько часов)

### 2.1 Старт сервера

```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Приложение подключится к публичному WebSocket Bybit, начнёт получать стакан BTCUSDT и ETHUSDT, рассчитывать признаки и генерировать алерты.

### 2.2 Открой веб-интерфейс

Открой браузер: `http://127.0.0.1:8000`

Ты должен увидеть:
- статус подключения к бирже;
- актуальность стакана;
- текущие признаки: imbalance, spread, delta, microprice;
- свежие алерты (если стратегия сработала);
- открытые paper-сделки.

### 2.3 Создай paper-сделку вручную

Когда появится алерт, нажми кнопку **paper**. Сделка откроется с текущей ценой, стопом и целью. Статус изменится на `paper_opened`.

### 2.4 Оставь приложение работать

Для обучения модели нужна история. Оставь сервер на несколько часов или дней, чтобы накопить закрытые paper-сделки. Можно периодически открывать алерты вручную или дождаться автоматического закрытия по стопу/цели (требует отдельного модуля мониторинга, пока не реализован).

## Этап 3: Обучение CatBoost (после сбора истории)

### 3.1 Установка ML-зависимостей

```powershell
pip install -e ".[ml]"
```

Это установит CatBoost, Pandas и PyArrow.

### 3.2 Экспорт данных в Parquet

```powershell
python -m app.ml.export
```

Проверь каталог `data/history` — там должны появиться файлы:
- `alerts_YYYYMMDD_HHMMSS.parquet`
- `trades_YYYYMMDD_HHMMSS.parquet`

Это сжатые колоночные архивы всех алертов и сделок.

### 3.3 Обучение модели

```powershell
python -m app.ml.train
```

Скрипт объединит алерты с закрытыми сделками, разметит их как `1` (прибыль) или `0` (убыток), обучит CatBoost и сохранит модель в `data/models/signal_filter.cbm`.

Ты увидишь:
- количество собранных сделок;
- win rate;
- важность признаков (feature importances).

Минимум для обучения — 50 закрытых сделок. Если их меньше, собирай историю дольше.

### 3.4 Включи фильтрацию в production

Добавь в `.env`:

```
USE_ML_FILTER=true
ML_MODEL_PATH=data/models/signal_filter.cbm
ML_THRESHOLD=0.55
```

Перезапусти сервер. Теперь каждый сигнал будет проверяться моделью: если вероятность успеха ниже порога, алерт не будет создан.

## Этап 4: Проверка производительности

### 4.1 Скорость обработки стакана

В логах сервера должны быть сообщения вида:

```
INFO app.market.service paper alert BTCUSDT LONG score=0.682
```

Если задержка между обновлением стакана и расчётом признаков меньше 100 мс, система работает быстро.

### 4.2 Размер Parquet-файлов

Проверь размер файлов в `data/history`. Parquet должен быть в 5–10 раз меньше, чем эквивалентный CSV.

### 4.3 Время предсказания CatBoost

Каждое предсказание модели должно занимать менее 1 мс. Это проверяется автоматически при включённом `USE_ML_FILTER=true`.

## Этап 5: Docker-проверка (опционально)

Если хочешь проверить PostgreSQL-режим:

```powershell
docker compose up --build
```

Приложение запустится с PostgreSQL вместо SQLite. Интерфейс доступен так же: `http://127.0.0.1:8000`.

После полного теста ты должен увидеть:

1. **Веб-панель** с реальными рыночными данными BTCUSDT/ETHUSDT.
2. **Алерты** с причиной срабатывания и признаками order flow.

## Частые проблемы

### WebSocket не подключается
- Проверь доступ к `stream.bybit.com` (может быть заблокирован в твоём регионе или firewall).
- Попробуй testnet: `wss://stream-testnet.bybit.com/v5/public/linear`.

### Нет алертов
- Стратегия очень консервативна: нужны имбаланс ≥0.22 + дельта ≥0.18 + микропрайс-подтверждение.
- Измени пороги в `app/strategy/orderflow.py` или жди более активного рынка.

### Ошибка "Not enough trades for training"
- Нужно минимум 50 закрытых paper-сделок.
- Открывай больше алертов вручную или жди дольше.

### Ошибка импорта NumPy/CatBoost
- Переустанови зависимости: `pip install --upgrade -e ".[dev,ml]"`.

## Следующий шаг

После успешного теста paper-режима с CatBoost-фильтром можно:

1. Добавить Telegram-уведомления (отдельный модуль).
2. Добавить автоматическое закрытие paper-сделок по стопу/цели.
3. Подключить больше символов.
4. Мигрировать на PostgreSQL для постоянной работы.
5. Развернуть на VPS с автоматическим перезапуском.

**Реальные ордера** можно добавлять только после:
- проверки положительного ожидания на paper-сделках;
- walk-forward тестирования модели;
- создания отдельного модуля с подтверждением и emergency stop.
